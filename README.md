# Hero's Land 自动打怪 + 拾取脚本

对着《Hero's Land（英雄之地）》的实机画面做的视觉自动化脚本：**WASD 走位 → 靠近野怪 → 按住左键砍 → 怪死掉后绕尸体一圈把掉落全部捡起来**。
不攻击玩家，也不攻击带名字的宠物 / Boss。

---

## 快速开始

1. 先启动游戏并进入对局（沙盒模式），窗口保持**全屏/无边框窗口化**，分辨率 1920×1080（125% 缩放也可以，脚本会自动换算）。
2. 双击 `run_bot.cmd`（它会用 `-ExecutionPolicy Bypass` 调起 `run_bot.ps1`）。
3. 脚本会自动把游戏窗口切到前台并开始跑。想停就按 **F10**，临时挂起按 **F9**。

> 运行期间鼠标会被脚本接管（攻击时会把指针移到怪身上）。停止后会自动把鼠标放回原位。

## 热键

| 按键 | 作用 |
| --- | --- |
| `F9` | 暂停 / 继续 |
| `F10` | 停止并退出（会松开所有按键、恢复鼠标位置） |
| `ESC` | 停止（注意：游戏里 ESC 同时会打开设置菜单） |

## 它怎么判断该打谁

全部靠画面识别，不读写游戏内存、不发协议包：

| 目标 | 视觉特征 | 处理 |
| --- | --- | --- |
| 野怪 | 只有一条**红色血条** + 左侧等级徽章 | ✅ 攻击 |
| 玩家 | 红/绿血条**上下还叠着蓝色护盾条或橙色体力条** | ❌ 跳过 |
| 宠物 / Boss / 精英 | 血条上方或下方有**名字牌**（深色底 + 白字） | ❌ 跳过 |
| 自己 | 离屏幕中心最近、带徽章的那条**绿色血条** | 定位用 |

只有"孤零零一条红条"的实体才会被当成野怪，因此玩家图标、队伍成员、带名字的 BOSS 都不会被误打。

## 体力（橙色条）管理

- 橙色条就是体力。体力低于 `-StaminaLow`（默认 22%）时，脚本会**停止攻击**、后撤，等回到 `-StaminaHigh`（默认 55%）以上再继续打。
- 默认就用左键攻击（更稳）；E 模式保留作可选项。攻击时如果血条 1.5 秒没掉，会自动把点击点上/下移动几个位置重新试（对准怪物身体而不是头顶血条），7 秒还没伤害就放弃这个目标换下一个。

## 打怪手感（2026-11 调整）

- **近身就按住不放**：目标进入 230px 后立即按住左键并一直保持（不再松手、不再重点），边挥边往前走，直到目标消失才松开。
- **瞄准**：怪在移动时鼠标压在怪身上并逐帧跟随；静止时瞄到它身后 55~145px，让挥砍轨迹穿过它。瞄点会随时间微调，但**不会松开按键**。
- **黑血条也是活怪**：引擎现在会额外识别"只剩黑灰色空槽"的血条，把它当成 HP=0 的活怪继续攻击。以前红条一消失目标就从列表里掉了，脚本以为怪死了就跑开——这就是"打到一半就走/不捡东西"的主因。
- **不会把自己当怪**：玩家自己的蓝色护盾空槽也是灰的，容易误判成怪；现在凡是紧挨着绿色血条的黑条一律排除。
- **尸体保护**：黑条持续 6 秒还没消失，判定为尸体，拉黑 10 秒换目标。
- **宝箱同理**：宝箱上方的小格条还在就说明没开，继续砸；砸两下碎掉才进入拾取。
- **追怪超时**：超过 230px 的远目标追 **5 秒**还追不上就放弃，拉黑 10 秒换目标。
- **边打边捡**：战斗中每 0.6 秒补按一次空格；拾取时若身边 230px 内还有怪，也会保持左键继续砍。

## 安全区（传送门）

画面里出现那种**大蓝色传送门光圈 + 石砖地面**时，说明进入了安全区：

- 安全区内**攻击无效**，所以脚本停止一切攻击行为
- 但可以**拾取**：有掉落物就走过去并按空格
- 血量没满就**站着回血**，直到 90% 以上
- 血满且没有掉落物时，会主动**走出安全区**继续打怪（避免一直蹲在里面）
- 如果人在外面、血量掉到 45% 以下，看到传送门会主动**跑进去回血**

识别方式：找画面里的大号蓝色光圈（半径约 120px、饱和蓝、有环形结构），用它的圆心和半径判定"是否在圈内"（半径 ×1.35 + 40px 的容差）。参考截图实测能定位到 `cx=295 cy=153 r=123`。

## 防卡死（不攻击也不捡拾）

之前会出现"打完怪站在原地不动"的僵局，来自四个互斥的等待状态，现在都加了上限：

| 状态 | 旧行为 | 现在 |
| --- | --- | --- |
| 打完怪后的 hold（等血条确认） | 最久 8 秒原地挥空 | 上限 3 秒，且会朝目标最后位置走过去重新锁定 |
| 体力休息 | 体力条读数不对就一直后退 | 最多 6 秒强制恢复 |
| 低血逃跑 | 血量误判就一直逃 | 最多 6 秒强制恢复 |
| 任意状态 | — | **2 秒没有任何输入就强制走一步**（`[idle] watchdog`） |

另外 SPACE 改成**全局常按**（每 300ms 一次，任何状态下都按），所以只要脚下有掉落物就会被捡起来，包括正在打怪、正在追击、正在开箱的时候。

## 拾取（优先级高于继续打怪）

怪被打死的那一刻就进入拾取状态，**在此期间不会去追新出现的怪**（除非血量掉到 45% 以下先保命）。

拾取不是按固定屏幕坐标，而是以角色当前位置为基准走一个"十字花"路线：左 → 右 → 上 → 下 → 左上 → 右下，单次约 5 秒（8 段），全程每 0.19 秒补按一次空格，覆盖半径约 ±120px。这样即使镜头跟着角色移动、尸体在屏幕上发生位移，也照样能踩到掉落物上。

平时赶路、搜索目标时也会持续补按空格，顺手捡起脚下的东西。

## 宝箱

宝箱＝"不会动的怪"，走**完全相同的流程**：进目标列表 → 靠近 → 按住左键砍 → 打两下碎掉 → 原地掉落 → 进入拾取状态把东西捡走。

识别方式：把画面按 1/3 降采样后取"箱体颜色"连通域（木板之间的深色缝隙会被横向膨胀合并成一块），再用三个条件确认：

1. 箱体颜色：普通箱是橙棕色（≈ #C47E39），高级箱是紫色（≈ #673E9C），两套色域分别跑一遍
2. **左右两侧都要有灰色石框**（箱子最标志性的结构，能排除木桶、木栅栏）
3. 尺寸 40~200px、长宽比 0.6~1.85、填充率过滤

实测两张参考图（普通箱 / 紫箱）都能各识别出 1 个，实机跑 30 秒无误报。

因为和怪同一条流水线，攻击距离自学习、5 秒换目标、击杀后捡取这些都自动复用。宝箱不会动，所以瞄的是箱体中心；如果敲了 3 秒还没碎，视为误判并把这个位置拉黑 12 秒。

## 掉落物光柱

同时也会识别"竖直彩色光束"来定位掉落物：走到光束底部并按空格；移动时按屏幕象限决定 WD/WA/SD/SA 方向。光束判定比较保守（细高、饱和、避开自己和玩家、避开 UI 区）。场景特效偶尔会被误判，如果发现它去追一个空位置，用 `-ShotDir` 看一眼标注框就能确认。

## 避障

镜头始终把角色固定在画面里，所以"有没有在移动"不能看角色坐标，脚本用了两个信号：

1. **背景滚动量**：每帧对游戏区域做稀疏采样，和上一帧比较，算出画面变化比例（站桩约 0.02，正常行走 0.13~0.30）。按住方向键但变化量长期低于 0.055，就判定撞墙/撞树。
2. **追击距离停滞**：追怪时 1.2 秒内到怪的距离没有缩短，且背景也没滚动，说明路被挡住。

两种判定都会触发同一套脱困动作：**先朝反方向退半步（连续卡住时退得更远），再转 90° 换个方向走**；追怪时的绕行是朝目标方向的垂直方向侧移约 950ms，左右交替，绕过去后自动继续追。

## 常用参数

```powershell
# 跑 10 分钟
.\run_bot.ps1 -DurationSec 600

# 只识别不操作（调参/验证用，不会抢鼠标）
.\run_bot.ps1 -DryRun -DurationSec 10

# 改用 E 自动攻击开关（默认就是左键攻击，一般不需要）
.\run_bot.ps1 -Engine e

# 体力阈值调高一点，更保守
.\run_bot.ps1 -StaminaLow 0.35 -StaminaHigh 0.7

# 存下识别标注图，方便看它到底锁定了谁
.\run_bot.ps1 -ShotDir .\shots -ShotEvery 5
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-DurationSec` | 0 | 运行秒数，0 = 一直跑到热键 |
| `-Engine` | `lmb` | `lmb` = 按住左键攻击（默认，稳定），`e` = E 自动攻击开关（部分场景/模式不生效） |
| `-AttackRange` | 120 | 进入攻击距离的像素阈值（1080p 基准） |
| `-Fps` | 8 | 主循环频率 |
| `-StaminaLow` / `-StaminaHigh` | 0.22 / 0.55 | 体力下线 / 恢复上线 |
| `-ShotDir` / `-ShotEvery` | 空 / 0 | 保存带标注的截图 |

## 文件结构

```
herosland_bot/
├─ run_bot.cmd        双击启动
├─ run_bot.ps1        主逻辑：状态机 / 走位 / 攻击 / 拾取 / 体力
├─ HeroBot.cs         视觉与输入引擎（Add-Type 现场编译）
│                     · PrintWindow 后台截图（不抢焦点也能看画面）
│                     · 血条连通域检测、颜色分类、名字牌识别
│                     · SendInput 键盘鼠标（扫描码，兼容游戏）
└─ tools/             调试用小工具（analyze / probe_* / find_and_e*）
```

`tools\analyze.ps1` 最常用：`powershell -ExecutionPolicy Bypass -File tools\analyze.ps1 -Out ann.png` 会把当前帧识别到的怪物（绿框）、玩家（橙框）、自己（青框）画出来，方便确认阈值。

## 已知限制

- 游戏窗口必须在前台，否则脚本会自动暂停（避免把按键发到别的窗口）。
- 只识别**屏幕内**的目标；贴着屏幕最边缘、被小地图/背包面板压住的目标会被忽略（这正是为了不误点 UI）。
- 怪物会移动，近距离目标偶尔会丢一帧，脚本用"目标锁定 + 追踪最后位置"来兜底。
- 沙盒地图怪物有刷新节奏，空旷区域会一直走位找怪；想效率高就把它丢在怪物多的区域。
- 分辨率不是 1920×1080 也能用（按画面高度等比换算），但偏差过大时需要重调 `-AttackRange`。
- 自动化脚本可能违反游戏用户协议，请自行权衡使用场景（建议只在自己玩、且不影响其他玩家的环境里用）。












## 换台电脑跑不起来？先看这里

脚本是纯 PowerShell + 运行时编译的 C#，依赖很少，但 Windows 有几道常见的"拦路虎"：

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 窗口一闪而过 / `找不到 HeroBot.cs` | 只下载了 `run_bot.ps1` 一个文件 | 现在引擎源码已内嵌在 `run_bot.ps1` 里，**单独一个文件也能跑**，首次运行会自动还原 `HeroBot.cs` |
| `无法加载文件 ... 因为在此系统上禁止运行脚本` | PowerShell 执行策略 / 组策略 | 右键 `run_bot.cmd` 用管理员运行一次，或在 PowerShell 里执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| 下载后提示"已被阻止" | 文件带"来自 Internet"标记 | 右键 `run_bot.ps1` → 属性 → 勾选"解除锁定" → 确定 |
| 报错或直接被删 | 杀毒软件拦截（脚本会发送键鼠、截屏、编译 C#） | 把文件夹加入杀毒白名单 |
| `PowerShell 5.1 or newer required` | 系统 PowerShell 太旧 | 升级到 Windows PowerShell 5.1 或 PowerShell 7 |
| `Hero's Land not running` | 游戏没开，或进程名不是 `HerosLand` | 先启动游戏并进入对局；独占全屏改成"无边框窗口" |
| 能跑但不动 / 识别不到怪 | 分辨率或 UI 缩放差异过大 | 用 `-ShotDir .\shots -ShotEvery 5` 存图，看识别框是否对准；再调 `-AttackRange` |
| 一直走但没怪 | 所在区域怪被清空了 | 换个怪物多的区域，或让它自己巡逻 |

自检命令（不接管鼠标键盘，只识别）：

```powershell
.\run_bot.ps1 -DryRun -DurationSec 5
```

能打印出 `hunt/fight/...` 状态行就说明环境没问题，剩下只是识别参数的事。
### 游戏里没反应？先跑自检

```powershell
.\run_bot.ps1 -SelfTest
```

它只做三件事：把游戏切前台 → 按 1.3 秒 W → 把鼠标移到屏幕中间，然后打印结果：

```
--- input self test ---
window handle : 918912
foreground    : True
move test     : background motion 0.672  (>0.05 = the character moved)
PASS: keyboard reaches the game.
mouse test    : cursor (158,1035) -> (960,540)
PASS: mouse movement works.
```

| 结果 | 含义 | 处理 |
| --- | --- | --- |
| `foreground: False` | 抢不到前台焦点 | 关掉"独占全屏"，改成无边框窗口；别在运行时点别的窗口 |
| `move test` 失败（motion < 0.05） | 键鼠事件被系统丢弃 | **游戏是管理员权限运行、脚本不是** → 右键 `run_bot.cmd` 以管理员身份运行；或杀毒/反作弊拦截 |
| `mouse test` 失败 | 鼠标没被移动 | 同上，UIPI 拦截 |
| 两项都 PASS | 输入正常，问题在识别 | 用 `-ShotDir` 存图看识别框 |

> 自检通过但游戏里还是不动，通常是**窗口在跑的过程中失去焦点**：脚本会打印 `[focus] game is not foreground - retry #n`，把鼠标移回游戏窗口即可。
